# Unity WebGL 电路虚拟实验分析

默认交付**元器件、电路搭建、实验报告**三部分答案。用户可以直接照着勾选、接线和填表。以当前实验的具体任务、当前模式和实际界面为准。若用户仅要求审查特定链路，按其指定范围工作。

## 开始

1. 有文件或已有分析时，先盘点实验目录。复用已有 profile、解析器和取证成果，找到当前构建的 Unity DATA、场景、WASM、metadata。记录支持结论的文件 SHA-256。阅读 [答案工作流](answer-workflow.md)，直接走答案提取路线。
2. 有接线资料时，优先查看当前实验的清晰正视面板图。已有图片时直接用。没有图，且无法从与当前场景匹配的资源确认可见印号时，尽早请求用户提供**电路搭建面板截图**，要求能看清编号、插孔及设备。若多个挂箱、任务或视角的布局不同，请用户补齐对应图。等待时继续提取元器件和报告。
3. 仅在用户要求采集时读 [采集工作流](capture/workflow.md)。用户手动操作实验，agent 处理材料。已有本地产物足以回答时直接使用。
4. 需要定位判分证据时，用 [取证参考](reference.md) §R5 的原有映射流程。优先追到三部分答案的来源与消费者。三个交付物所需证据已齐即可停止，完整红格阈值、提交实现和所有函数的逆向属于单独任务。

## 按顺序提取和核对

- **元器件**从当前场景引用的答案配置入手。把勾选位、枚举或 ID 沿 UI 初始化映射到可见顺序和名称，再核对判分消费者。
- **电路搭建**先还原当前任务的连通组或直接线对，再把 **Unity 内部 ID 映射到面板可见编号**。用端子位置、器件归属和截图交叉核对，排除保险丝座、开关和装饰。重复内部 ID 用所在面板、父对象或坐标消歧。没有证据时保留已确认的部分，缺号的任务标成待核对。
- **实验报告**要追字段实际读取的期望值或计算来源，与当前输入界面的行、列、单位和模式逐一配对。导出 HTML 可能沿用旧模板，截图或场景里的实际输入表优先用于定位填写位置。

## 交付格式

固定用 **1. 元器件**、**2. 电路搭建**、**3. 实验报告**。元器件按可见序号和名称列出。接线用纯文本代码块，每个任务或电容档一行，每组用十进制印号写成 `1-12-9`，组之间留空格。先说明连字符含义，验证过可串接时才按相邻两端接线解释。报告用纯文本代码块，表头含单位，各行按界面顺序，保留小数和正负号。完整模板与部分交付的写法见 [答案工作流](answer-workflow.md)。

## 验收与边界

- 当前场景或运行时初始化指向的配置，加上消费者和界面映射，才能支撑答案。找到方法名、计数吻合、成功反编译或 `dgmap --check` 通过均属于中间证据。
- 历史 `wrong` 仅用于佐证那次提交。未知规则和未知端口不生成增线或拆线指令。区分已证、推断和未确认，缺数据时说明具体阻塞。
- 收尾标明本地静态核对范围和实际是否验分。原始材料只读，派生证据脱敏。动态操作、请求重放和在线提交需要单独授权。
- DG10 保留原有映射回归。DG11 有覆盖三项答案的本地复跑样例。[DG11 复跑命令](answer-workflow.md#dg11-复跑样例) 仅适用于已核对的构建及对应面板。
