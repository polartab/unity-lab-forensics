# 三部分答案工作流

## 1. 先确定哪份配置生效

1. 定位当前实验的场景与题名、任务名、模式。先查已有解包结果，用 `rg --files` 找 `level*`、`sharedassets*.assets`、`resources.assets`、`globalgamemanagers.assets`、`*.wasm`、`*.wat` 和 `global-metadata.dat`。
2. 只有容器时，用下列脚本解包到派生目录。先按 `--list` 或 `list` 确认格式。路径变量替换成实际文件和新目录。

   ```bash
   python3 -B "$SKILL_DIR/template/tools/unitywebdata.py" "$WEBGL_DATA" --list
   python3 -B "$SKILL_DIR/template/tools/unitywebdata.py" "$WEBGL_DATA" --extract "$EXTRACTED"
   python3 -B "$SKILL_DIR/template/tools/unityfs.py" list "$UNITY_BUNDLE"
   python3 -B "$SKILL_DIR/template/tools/unityfs.py" extract "$UNITY_BUNDLE" "$SCENE_ASSETS"
   ```

   上述解包器读取相应的解压后容器。浏览器缓存条目先按 [取证参考](reference.md) §R5 提取。已有对应场景文件可跳过解包。

3. 优先查**场景引用**。从当前场景管理组件的答案数据字段，追 Unity PPtr（文件索引和对象 Path ID）到实际资产，再查 WASM 是否读取该对象或在初始化时替换它。候选名字可用 `DataStorageOptimal`、`TaskAnswerList`、`ReportAnswerList`、`DeviceAnswer` 开始，具体名称按该构建确认。别漏掉跨文件的 ScriptableObject 或没有 GameObject 所属的 MonoBehaviour（两者都可能序列化为类 ID 114）。
4. 对 Unity 2018 使用的 **小端、去除类型树的 v17** 序列化文件，可运行下面的只读定位工具。它列出匹配组件的对象 Path ID、偏移和大小。脚本文件索引要与该序列化文件的外部引用表一致。遇到其他布局，按现有解析器或能读取该布局的本地 Unity 资源查看器继续。匹配类型只是候选，仍需核对场景的真实引用。

   ```bash
   python3 -B "$SKILL_DIR/scripts/unity_scene.py" \
     "$SCENE_ASSETS/sharedassets0.assets" \
     --scripts "$SCENE_ASSETS/globalgamemanagers.assets" --file-id 1 \
     --type DataStorageOptimal
   ```

5. 若场景不含期望数据，再查当前任务确实读取的 TextAsset、初始化响应和计算函数。按消费者实际使用的字段区分客户端期望值、仿真读数和服务端结果。通用资源可能含其他实验题名或旧接口。DG11 的 `JsonDataSHow` 属于这个易混淆分支，不能因为它的键名像答案就替代场景配置。

## 2. 元器件

- 找勾选集合或位串及其读取函数。沿 UI 创建顺序追列表索引，记录序号、显示名称、内部 ID。若同一器件在各任务状态不同，按任务分别列出。
- 用实际判分读取的顺序展开位串。确认位置用从 1 开始的用户界面序号。器件出现在场景、说明书或电路中，只能支持候选清单。

## 3. 电路搭建

- 按每个任务读取配置，区分必须同网的固定端点、可互换的元件端子、必须直连的线对、禁止项。只有判分确实接受同网等价时，才把一组写成链式连接。一个可互换元件的两端要分别落在正确的两组里，禁止在同一组短接该元件。只能证明直接线时逐条用 `A-B` 展示。
- 用同一任务的清晰正视面板图核对**每个被用到的可接线插孔**。图中要看得清印号和器件归属，不能靠序号后缀猜。若有多块面板，连线数字仍保持纯十进制，用外层标题说明面板，用跨面板线的文字明确两端分别所属的面板。
- 从端子 GameObject 找父级器件名和 Transform（位置变换）；对照图上的几何位置和印号；对容易读错或同名的端子，用至少三个分散锚点校正方向和比例，再逐一核对。不规则或透视面板应分区核对，避免用简单坐标拟合强行配对。纹理、示意图与实时面板不一致时，以实际可操作插孔为准，并记录差异。
- 为用到的端点保留可追溯关系 `内部 ID → 父级器件 / 位置 → 面板印号`。检查不同连通组没有意外共用插孔、所有展示的编号在对应面板中唯一可用、未出现保险丝座或开关，且每行确实属于该任务。用核对后的方案反代内部规则，确认每个必需组和可替换对均满足。
- 缺面板图且本地资源不足时，直接请用户发「电路搭建页面的完整正视截图，能看到每个插孔的十进制编号、器件名称和当前任务」。位于同一面板的多个角落看不清时，可以补局部图。继续做另外两个部分。某档有端点未映射时，显示该档缺什么，禁止输出看起来已经可照接的整行。

## 4. 实验报告

- 找判分实际读取的输入字段和期望值数组。按场景的输入组件顺序核对表头、固定标签及坐标，将数组拆到具体行与列。单元格数只是交叉检查。不同模式和不同表分别核对。
- 明示固定预填项。保持期望文本的精度、符号和单位。由实测信号、服务器或当前状态决定的值，应注明来源和缺失信息。若只确定公式，按用户需要给公式和待输入量，不以常见理论值当成该实验的期望答案。
- 若历史提交为空或 HTML 导出的行标签跟 UI 不一致，记录差异；继续以真实输入字段与判分来源核对可填写的答案。

## 5. 输出模板

以下数字为格式示例。填写本次实验的已核对数据。用户只问其中一项时直接交付该项。

````markdown
## 1. 元器件

- **第 3 项** 器件名称
- **第 7 项** 器件名称

## 2. 电路搭建

以下使用面板印号。每行是该档的完整接线。
`1-12-9` 表示接 `1-12` 和 `12-9`，空格隔开的组独立连接。

```text
任务1  1-12-9  4-16
任务2  1-12-9  4-16-18
```

## 3. 实验报告

U 已预填 220 V。

```text
C (μF)  P (W)  U (V)  I (mA)  cos φ   φ (°)
0       34.2   220    319     0.50    60
```

已用本地构建静态核对，尚未在线验分。
````

短注明每部分的实证来源。未完成的栏目保留标题，用「待核对」和具体缺项替代示例。不要把技术日志堆到答案前面。

## DG11 复跑样例

`dg11_answers.py` 从 DG11 当前已核对的构建读取专用配置，校验实际场景引用，输出上述三段。它依赖同一目录下的 `unity_scene.py`，只用 Python 标准库。

```bash
python3 -B "$SKILL_DIR/scripts/dg11_answers.py" "$DG11_ROOT"
```

核对当前面板与样例后，才添加 `--panel-matches-reference` 生成数字接线。样例为 HKW-03 日光灯组件，按当前截图确认以下印号：左上电源 L1 为 1、左侧 N 为 3，电压表为 5/6，电流表为 7/8，灯管四个插孔为 11/14 与 15/16，**12/13 为保险丝座**，镇流器为 17/18，启辉器为 19/20，C1/C2/C3 为 21/22、23/24、25/26。若发现实际界面差异，保留提取结果并重新映射。`--panel-matches-reference` 表示已由人工确认面板。返回码 0 表示输出了三个栏目，1 表示待确认面板且已输出元器件和报告，2 表示提取失败或构建不匹配。

以下位置可用来复核。

- `level0` 的 Manager 对象 44718 引用 `sharedassets0.assets` 的对象 2313，名为 `11PowerFactorImprovement`。`CanShowImage[27936]` → `ElectricCenter.NewJudgement[51317]` 读取该对象的任务连通组。
- `ProjectThreeMethod` 的实际校验体 [51130] 从该对象读 `DeviceAnswer`。列表初始化 [51378/51380] 以及名称映射 [23989] 证实应勾选第 3、7、8、9、12 项。
- 内部 `HKW-0312` 是面板 16，`HKW-0313` 是面板 17。内部 `HKW-0302` 和 `HKW-0304` 分别有重复对象，按交流电源和电压表的父级选面板 3 和 6。0 μF 的完整回归行是 `1-5-7  8-17  15-18  11-19  14-20  3-6-16`。
- 报告 [51126] 初始化真实输入顺序，[51132] 读 `ReportAnswerList`。虚拟仿真有 0–6 μF 七行，每行六格，U 固定 220 V。导出 HTML [51409/51410] 的 8/15/30 μF 是另一路的硬编码行标签。
- 文件哈希、对象 ID、字段偏移、WASM 函数编号和面板映射只适用于该样例。未匹配时回到本页通用步骤。
